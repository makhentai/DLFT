# DownloadListFromTushenka — дизайн

Дата: 2026-09-03

## Цель

Консольная утилита для Windows, которая по публичной/скрытой ссылке на
список модов сайта sp-mod.com («The Forge») скачивает все моды и аддоны
из этого списка в подпапку `Download`, используя официальный открытый
API (`https://sp-mod.com/api/v0`) для получения точных ссылок на файлы.

Запускается без предварительной установки чего-либо (`.NET`, зависимостей) —
собирается как self-contained single-file exe.

## Не входит в объём (non-goals)

- Не строится дерево зависимостей самостоятельно: список на сайте уже
  включает зависимости как отдельные записи (проверено на тестовом
  списке — зависимости отмечены тегом «Dependency» и присутствуют как
  обычные пункты списка).
- Не проверяется совместимость с версией SPT пользователя вручную/интерактивно.
  Начиная с 2026-09-15 `ForgeApiClient` сам сверяет `spt_version_constraint`
  версии, показанной на странице листа, с диапазоном 4.1.x (4.1.0–4.2.0,
  под который собран этот проект): если она не подтверждена, берётся
  новейшая версия мода, у которой `spt_version_constraint` пересекается
  с 4.1.x, с предупреждением в лог о подмене; если такой нет вовсе —
  берётся просто новейшая доступная, с более резким предупреждением.
  Причина: сайт может показывать устаревшую версию в момент скрейпинга
  (репортился случай, когда пользователь получил файл под SPT 4.0.13 из
  листа, курируемого под 4.1.x — точный виновный мод не установлен, но
  механизм воспроизводится: например, у Manimal's Icebreaker Backport
  версии до 1.0.0 несли `spt_version_constraint: "~4.0.13"`). Диапазон
  4.1.x зашит константой
  (`ForgeApiClient.TargetRangeMin/Max`) — при переезде сборки на другую
  версию SPT его нужно поменять там.
- Не устанавливаются моды в игру (не копируются в папку SPT/BepInEx и
  т.п.) — только скачивание файлов в `Download`.
- Аутентификация не требуется и не реализуется — API и страница списка
  публично доступны по ссылке.

## Входные данные

Пользователь передаёт URL списка вида:

```
https://sp-mod.com/list/{listId}/{slug}/{accessToken}
```

Утилита принимает произвольный URL в этом домене как аргумент командной
строки.

## Архитектура

Три последовательных этапа, каждый — отдельный, тестируемый независимо
компонент:

```
ListPageFetcher → ListHtmlParser → ModEntry[] → DownloadLinkResolver → ResolvedDownload[] → FileDownloader → Download/*.zip
```

### 1. `ListPageFetcher`

Обычный `HttpClient.GetStringAsync(listUrl)`. Cloudflare не блокирует
запросы с обычным `User-Agent` (проверено `curl`) — специальных заголовков
не требуется, кроме описательного `User-Agent`, как просит API
(«Be a good citizen: send a descriptive User-Agent»).

### 2. `ListHtmlParser`

Парсит HTML через **HtmlAgilityPack** (NuGet, чистый managed-код, без
нативных зависимостей — совместим с single-file publish).

Для каждой карточки мода/аддона в списке извлекает:
- тип: `Mod` или `Addon` — определяется по сегменту пути ссылки
  (`/mod/{id}/{slug}` или `/addon/{id}/{slug}`);
- `Id` (int) и `Slug` (string) — из href;
- `Name` — текст ссылки;
- `Version` (string) — из соседнего `<span class="shrink-0 text-xs text-gray-400">`.

Найденная разметка (пример, проверено на тестовом списке):

```html
<a href="https://sp-mod.com/mod/2905/ragdoll-kinetics" ...>Ragdoll Kinetics</a>
<span class="shrink-0 text-xs text-gray-400">1.2.0</span>
```

Селектор: все `a[href]`, чей путь матчит `^/(mod|addon)/(\d+)/([^/]+)$`;
версия — из первого `span` с классом `shrink-0 text-xs text-gray-400`,
следующего за этой ссылкой внутри общего родительского блока карточки.

Если структура страницы не совпала (0 найденных записей) — понятная
ошибка с предложением проверить ссылку/сообщить, что разметка сайта
изменилась.

### 3. `DownloadLinkResolver`

Для каждой найденной записи запрашивает официальный API:

```
GET /api/v0/{mod|addon}/{id}/versions?filter[version]={version}
```

Из ответа берёт `link` (прямая ссылка на скачивание — она делает 307
редирект на реальный файл, например GitHub Releases) и `content_length`
(для прогресса, может быть `null`).

Если версия из списка не найдена в ответе API (список рассинхронизирован
с каталогом) — запись помечается как ошибка, обработка остальных
продолжается.

Между запросами — небольшая пауза (по умолчанию нет, т.к. лимит
~300 запросов/мин с запасом покрывает типичные списки в десятки
позиций), но `HttpClient` переиспользуется с ограничением параллелизма
(до 4 одновременных запросов), чтобы не долбить API последовательно
слишком долго и не быть агрессивным одновременно.

### 4. `FileDownloader`

Скачивает файл по `link` (`HttpClient` с `AllowAutoRedirect = true`,
достаточно, т.к. наблюдаемый редирект — 307 на прямой URL файла).

Имя файла: `{Slug}-{Version}{Extension}`. Расширение определяется из
`Content-Disposition` заголовка ответа, если есть, иначе из последнего
сегмента итогового URL после редиректа, иначе — `.zip` по умолчанию
(все встреченные моды SPT распространяются как zip-архивы).

Папка вывода: `Download/` рядом с exe (создаётся, если не существует).
Если файл с таким именем уже существует — скачивание пропускается
(повторный запуск утилиты на том же списке не перекачивает всё заново).

Скачивание нескольких файлов идёт с ограниченным параллелизмом (до 4
одновременно) для ускорения без чрезмерной нагрузки.

## Отчёт о ходе выполнения

В консоль построчно, по мере обработки каждой записи:

```
[12/63] Ragdoll Kinetics 1.2.0 ... OK (45.4 KB)
[13/63] Task Item Indicator 1.0.0 ... OK (128.3 KB)
[14/63] SomeMod 2.0.0 ... SKIP (уже скачан)
[15/63] BrokenMod 9.9.9 ... ОШИБКА: версия не найдена в API
```

В конце — сводка: скачано / пропущено (уже есть) / ошибок, и список
названий с ошибками.

## Обработка ошибок

- Ошибка сети при получении страницы списка (не 200, домен недоступен) —
  фатальная, программа завершается с ненулевым кодом и понятным
  сообщением.
- Ошибка резолва версии через API или ошибка скачивания конкретного
  мода — не фатальная, попадает в сводку ошибок в конце, обработка
  остальных модов продолжается.
- Таймаут HTTP-запроса — 30 секунд на запрос страницы/API, 5 минут на
  скачивание одного файла.

## CLI

```
DownloadListFromTushenka.exe <ссылка-на-список> [--out <папка>]
```

- `<ссылка-на-список>` — обязательный позиционный аргумент.
- `--out` — необязательный, по умолчанию `./Download` относительно
  расположения exe.
- Без аргументов — печатает подсказку по использованию и выходит с
  кодом ошибки.

## Сборка и распространение

.NET 8, `dotnet publish -c Release -r win-x64 --self-contained true
-p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true`.
Результат — один exe, запускается на чистой Windows без установки
.NET или иных зависимостей.

## Тестирование

- Юнит-тесты `ListHtmlParser` на сохранённом HTML тестового списка
  (фикстура в репозитории, снятая с реальной страницы) — проверяют
  корректное извлечение всех записей (тип/id/slug/версия), включая
  edge-case записи с аддонами.
- Ручная (или e2e, если время позволит) проверка полного цикла на
  тестовой ссылке пользователя: `Download/` наполняется файлами,
  сводка совпадает с «62 mods · 1 addon» на странице списка.

## Открытые вопросы / допущения

- Разметка страницы списка — server-rendered Livewire HTML без
  версионирования; если The Forge обновит вёрстку, парсер сломается.
  Это принимается как известный риск (сайт не даёт JSON для списков).
- Расширение файла по умолчанию `.zip` — все встреченные примеры это
  подтверждают; если у какого-то мода будет другой формат, определится
  через `Content-Disposition`.
